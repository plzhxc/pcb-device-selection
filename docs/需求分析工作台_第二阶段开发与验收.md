## 1. 已实现的产品能力

中心对话和原有画布保留，增加两层专业视图：

- **模块方案**：按10大类浏览60父类和197子类，搜索功能名称；查看功能边界、抽象角色、完整参数和工程卡。用户可以纳入、编辑或移除模块，设置实际独立电路数量、关联需求及实现边界。编号不作为用户操作要求。

模块画布、需求清单和文档引用同一版本。功能框架在已有模块方案时显示实际模块；模块关系另区分供电、数据、控制和时钟。图形仅表达需求方案，不表示器件引脚、网表或电路验证通过。

问题继续支持部分回答、暂缓、自由补充和排队；新增“优先决定”、影响说明、每个候选的取舍及字段/决策范围。已闭合字段可避免同一决定换名字重复询问。草稿、停止、重试、来源与版本规则沿用第一阶段。

## 2. 收敛与审核条件

新协议要求逐字段处理247项目录内容，章节总结不能代替细目。闭合状态为：已明确、明确不适用、明确委托设计阶段。用途、产品身份、核心场景与Must-have功能目标不能整体委托后续或标为不适用。

确认或委托都要保留用户原话与相关需求。产品核心目标和功能必须关联REQ；非核心字段如“无交付日期约束”可直接由逐字依据闭合，无需复制一条同义需求，之后需求变化仍触发保守复核。未知保持待确认，冲突单列。必须由硬件承接的功能要关联已确认或已委托的规范模块；软件、外部服务、系统级目标分别记录，不凭空添加电路模块。

终稿审核还要求无未答问题、无未确认需求、无数值检查问题、无待内部复核字段，并具备产品流程。达到条件只进入待审核，用户点击才批准；修改后旧审核失效。

旧项目不在打开页面时重写；下一轮AI分析将旧章节结论迁移成字段级账本，已提供信息继续复用。没有迁移的旧结果保留原阶段状态，不冒充第二阶段字段齐全。

## 4. 开发与复测脚本

在 `requirements_studio` 执行：

```bash
./scripts/phase2.sh build        # 重提取规范目录、类型检查与UI构建
./scripts/phase2.sh serve-real   # 独立真实CLI开发入口：[::1]:8892
./scripts/phase2.sh serve        # 独立受控验收入口：[::1]:8891
./scripts/phase2.sh test         # 核心和领域检查执行两遍
./scripts/phase2.sh accept       # 新建随机案例，自动管理隔离服务，浏览器及负载两轮
./scripts/phase2.sh accept-real  # 两个真实Codex产品会话；会消耗真实模型调用
./scripts/phase2.sh verify       # 目录、构建、核心两遍、受控两轮
./scripts/phase2.sh report       # 核对全部已保存证据并汇总
```

脚本不发布或覆盖正式项目。正式入口仍使用 `./start.sh` 的8878；开发构建位于 `.runtime/phase2-dist`。验收脚本会在结束后清理其Chromium临时用户目录，保留数据库、截图、JSON和模型收据。已占用隔离端口时脚本退出，不停止不明进程。

底层脚本包括 `scripts/build_phase2_catalog.py`、`tests/seed_phase2.py`、`tests/serve_phase2.py`、`tests/phase2_browser.mjs`、`tests/phase2_load.py`、`tests/phase2_real.mjs`、`tests/phase2_parent_browser.mjs`。真实案例中断后可使用 `node tests/phase2_real.mjs --resume` 沿用保存项目与问题，而不是重新开始。

## 5. 验收方式与证据

随机种子为20261016、20261017。两轮受控产品分别为工作台光照显示器、房间空气质量面板，并随机改变数值、类别、独立实例数量、字段分布和长内容；长案例含305项需求、160条历史消息、20个待答问题、20个模块。真人式浏览器操作覆盖类别搜索、详情、纳入/编辑/移除、键盘图节点、刷新、多尺寸、部分/暂缓回答、排队、停止恢复、故障、审核和修改。

受控测试明确标记 `controlled_phase2_fixture / real_inference:false`；真实Codex案例另存 `real_codex_cli`。不以受控替身的语义表现代替真实模型。网络请求和并发操作由实际HTTP服务执行，模型流程通过真实子进程接口进入系统。

全部证据在 `requirements_studio/.runtime/phase2/verification/`，核心日志在 `.runtime/phase2/unit-round-{1,2}.log`。历史失败和修正记录保留，最终结果以 `summary.json` 及成功的两轮报告为准。

## 6. 开发中发现并修正的问题

- 父类别缺少功能定义：补全60份原文契约和抽象角色，按类别语义选择。
- 源刷新添加默认实现责任导致无谓复核：按默认硬件语义比较，旧来源不因此失效。
- 模块说明改写反复打开字段：改为具体结构变化触发，需求变化另走关联失效规则。
- 日历年被误报未知单位：同单位检查，跨日历的物理计算不猜换算。
- 数值两个边界均null、只有结构没有有效事实：拒绝提交并把具体问题反馈给一次有界修复；不凭空补数值。
- 模型上下文重复长引文：无损分组，并用往返等价检查保证不丢证据。
- 明确没有交期却被要求补建同义REQ：非核心字段直接采用已有用户依据，避免无效重复提问；核心目标的关联要求保留。
- 审阅回合返回空流程而误清空旧流程：空数组表示本轮未修改，保留已记录流程；删除需求时只移除关联需求已全部失效的流程步骤。确实缺少流程时，路径画布明确显示阻塞原因和整理入口。
- 变更后复核清空原话依据：待复核字段另外保存上次依据，在界面标记为“上次依据（待复核）”，并保留到模型上下文；复核不能靠丢掉历史来减少缺口。
- 模型把外部供电名称当作模块实例端点：校验拒绝不存在的端点，反馈给一次有界修复。外部输入可以写入需求与边界；模块关系仅引用本版实际登记的实例。
- 模型抄短消息编号、将原话改写后作为引用：为本轮来源ID提供真实用户消息枚举，并在CLI保存前核对编号与逐字引文。错误进入内部有界修复，避免整批已知字段因引用格式问题退回待确认；不根据相似措辞猜测证据。对应两项真实子进程故障测试分别验证编号和引文修复，并确认用户消息没有重复增加。
- 单台成本被标为未知单位：支持人民币名称与元/CNY/RMB别名；“元/台”等单价只在核算对象明确为单台、每台等单一对象时参与同口径比较。整批预算与单价仍保留核对，不能凭100台批量自行乘除。
- 存储I/O失败后任务停留分析中：任务终止写入有限重试；持续失败时通过只读状态投影和SSE显示失败，恢复写入后可重试。接口返回明确的503说明，后台任务异常也会被接收处理，避免无声悬挂。
- CLI已返回但保存失败：重试可复用有成功收据、无越界工具/已知校验错误、同一用户消息与同一基线版本的原结果，重新执行完整来源和领域校验。收据记录`restored_from_run`；文档已变化时必须重新调用模型。真实照度案例用此路径恢复了一份原始CLI结果，没有直接改写需求数据库来制造通过。
- 旧版自动缺口问题混入内部复核：改用字段引擎更新后的复核范围；自动问题带字段关联，已有旧版自动问题会在对应字段有依据闭合后归档。已提供的产品名称不再因为内部复核被重复追问。
- 浏览器脚本曾在HTTP尚未提交时读取上轮状态，或把后台合理新增问题误判为部分回答丢失：改为等待本轮任务与界面版本同步，核对原有问题ID是否保留；不依赖问题总数必须下降。该问题属于验收脚本，失败截图保留。

真实案例还检出了有必要澄清的验收条件：测温范围、精度适用范围及“25±2°C下五个量程点”的含义应当明确；照度零点不能只靠读数百分比表述。此类产品决定与内部格式修复分开处理，不通过降级状态强行完成。
