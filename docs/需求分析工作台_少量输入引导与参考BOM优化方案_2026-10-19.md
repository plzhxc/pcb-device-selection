# 少量输入引导、参考网表和完整交接：实施方案

本方案根据《五案例真实用户压测与优化报告》制定，先记录决策，再开发。保留现有三视图与主库历史，在隔离环境实施和测试。

## 用户实际经过的过程

短需求 → AI 整理已知目标并提出一个高价值问题 → 用户回答一个使用取舍 → AI 更新功能、供电、接口和验收 → 可选上传参考网表/BOM → AI 读取参考器件与实际连接，形成适用方案 → 用户接受或调整少量取舍 → AI 补齐规范、能力链和核心器件清单 → 完整性检查 → 用户整体审核 → 交接。

用户不需要一次说全，不要求逐项输入芯片、引脚和外围参数。已有信息与参考资料由助手整理。没有回答时仍可整理独立内容，未答问题不会被自动接受。

## 1. 修复报告中已定位的问题

| 范围 | 实施决定 |
| --- | --- |
| F-01 | 尚未开始的内部 continuation 被新用户输入替代；已开始的任务不丢结果，完成后先处理用户输入。调度使用事务和状态比较，旧任务不能误启动。 |
| F-02 | 括号归属先判断系统、网络和接口职责。明确“组成电源网络、提供多电压轨”保留为产品目标，单颗芯片额定参数仍留在器件介绍。 |
| F-03 | 总括功能/流程/验收字段只刷新映射，不把所有共享需求加入语义复核；具体接口、模块、供电关联才扩大实际影响范围。 |
| F-04 | 区分排队、实际分析、保存和内部复核；展示真实队列位置/耗时，不编造预计时间。减少无变化 continuation，不单纯提高并发。 |
| F-05/F-06 | 默认阅读本项目已记录与待决定内容，未知规范合并折叠；完整规范仍可切换和导出。同一需求全文只在主要条款展示，其他位置使用短引用跳转。 |
| F-07 | 提供接口表格，保留连接位置、用途、协议/信号、电平和共用关系；一行可独立讨论或修改。附件提取的是参考连接，不自动认定为本版已验证接口。 |
| F-08 | 紧凑显示待用户决定、AI 内部任务、关键方案与后续工程任务；真实保存事件形成简短变更记录，不重复聊天。 |
| F-09 | 必须检查产品能力链：主控/转换器/固件/外部服务分别承担什么。型号名称不能代替端到端能力证据，冲突保留并提出取舍。 |
| F-10 | 需求审核、核心器件方案、参考BOM及完整电路生成准备分别显示；缺口列明承接对象和完成条件，不能隐藏在弹窗中。 |
| F-11/F-14 | 空待办是完成反馈；只有实际待处理的复核显示“AI复核”，其余是后续设计任务，不能无限显示无人执行的复核中。 |
| F-12/F-13 | 射频/开关/时钟频率分开，数值始终带单位；目录候选显示采购号、封装、来源和记录差异，允许查看详情，不盲选第一条。 |

## 2. 参考网表不是隐藏答案

增加真实的参考资料上传入口，支持现有 ENET JSON 和 BOM CSV。由服务端受限解析，不执行文件内容，不读取上传者未提供的路径。用户消息显示附件卡片，模型读取实际解析结果。

保存文件名、内容指纹、参考器件、位号、观测数量、采购号、封装和实际网络。参考器件清单与本版采用的器件方案分开；原始连接、复用/层次歧义有记录，不把原始对象数量无条件认作完整生产BOM。全文参考 BOM 可下载，核心器件默认展开。

AI 根据真实功能将参考器件关联模块，排除不需要的部分，给出少量可理解的推荐。用户可以采用已展示的器件方案，不必手工敲一长串型号；采用范围形成可追溯的记录。型号/数量来自参考还是用户新要求分别说明。数据库定位继续只读，未命中/多候选不冒充已核实。

没有参考时不强迫上传，继续通过使用场景、功能、预算和建议逐轮收敛；型号未确定的部分诚实保留为选型任务。不能靠“参考一致”宣称电气正确。

## 3. 什么才算可以停止本轮需求整理

不能只以“没有问题卡片”或“247字段有状态”判定完成。新会话需要：产品用途与边界、真实功能及可观察验收、外部供电、接口职责、适用模块与关系、系统能力链、核心器件方案及后续承接都有明确内容。存在影响目标的冲突、尚待客户决定的方案、缺失能力链或未归属核心功能时继续引导。

参考资料已提供时，应尽可能完成核心器件提炼与本版适用核对，再邀请整体审阅。无法核实的采购身份、电气条件和外围参数仍是显式设计任务，有负责人/完成条件；它们不能伪装成已验证数据。需求交接可用与完整电路生成就绪是两个门槛，后者仍由真实适配结果决定。

模型补充的方案必须有来源或标为建议；客户授权后可以采用明确展示的建议。没有授权，不能把“没说”当成“已委托”。有限内部任务耗尽但仍有缺口时明确显示下一步，不把状态改成完成，也不无限循环调用模型。

## 4. 验证方法

先补确定性回归：用户输入抢占排队内部任务、系统电压轨识别、局部依赖范围、完成状态一致、单位与频率、附件解析、BOM数量和导出完整性。再运行实际浏览器检查。

真实用户案例只用两个：按键发声玩具、小智语音板。每案首句是普通人会说的短需求；随后每次只回答当前的一项或紧密相关取舍。参考文件通过真实上传入口提供，不整段粘贴提示词，不让测试程序自动生成客户答案。

保留全部 UI 对话、选择、附件、版本、失败及修正。最终对照原参考 ENET/核心CSV，记录核心器件覆盖、遗漏/替代、数量、供电和接口的差异；不要求相同案例逐字一致，不执行后续网表生成。发布时备份并逐表核对原有项目不被覆盖。

## 5. 开发中的实际调整

- 发现内部复核立即抢占的阅读时间：有未答问题的内部续跑先等20秒，不占两个推理槽；新回答能事务性替换尚未开始的任务，未答仍继续。
- 未知专业模块字段仍在说明书尾部制造长页面：新增精简阅读尾部，保留已记录字段、关系图、BOM、工作流程；专业参考和全部来源可展开，下载的完整规范不裁剪。
- 没有被正文型字段引用的需求也必须有完整正文：统一放进补充要求，所有短引用都有跳转目标。
- 错误附件返回可读422，重复文件幂等；核心方案采用在事务内检查版本，避免旧清单误采用。下载原参考可校验原文件指纹。
- 后续工程待办直接在说明书与收敛页展开，列明负责人和完成条件；不隐藏在导出弹窗中。
- 功能验收不仅属于性能/生产分类：结构化交接同时保留已关联规范功能测试及核心验收检查的功能要求。

玩具参考中的电感使用U9位号，解析会列入主要器件，故提取5条，而原核心CSV为4条；这项额外参考是电源电感，不宣称它是一颗IC。语音板提取14条核心分组，BAT1/SPK1同一型号保留2个实例。最终采用数以实际会话验收记录为准。

## 6. 真实案例驱动的能力补强

语音板曾将参考Flash视为“未提出本地录音”，而固件启动存储是另一项基础运行前提。这不能只靠无问题卡片或模型自报四项完成来判断。参考信号投影增加实际共享网络及每个引脚的位号归属，同型号连接器不会丢失BAT1/SPK1各自信号位置。最终可审核前增加一次真实模型的参考能力复审，复核固件存储、时钟、供电/充电路径、接口与核心器件用途；四项检查必须有明确结论。真实产品架构、采用意图或物理用量改变后复审失效，只有时间戳变化不会重跑。

该检查仅证明已完成需求/参考方案复审，不代替电气设计或生产BOM验证；无关参考器件允许说明理由后不采用。依据：[Espressif官方ESP32-C3数据手册](https://documentation.espressif.com/esp32-c3_datasheet_en.html)，系列比较区分带封装内Flash的变体与需要封装外SPI Flash的ESP32-C3，不能把型号系列名称当成已解决固件存储。


实际复核继续修正：麦克风输出经C1耦合到编解码输入；编解码到功放之间有C7/C8及RC支路。只给直接共享网络会制造“参考未接通”的假缺口，故模型投影补齐原始无源两端连接。没有相同网名不能推出缺线，电容耦合也不能等同直流导通。该信息用于准确理解参考与整理工程任务，不把外围参数变成客户硬指标。

接口行式编辑仅提交客户实际修改的字段，其他内容实时沿用；提交后收起并显示真实待处理回执，过程中不重复提交。修改草稿按行保留，不随版本刷新被清空。维护接口工程更新省略检查点关联时，沿用这个稳定检查点已有、仍有效的需求关联；已取消需求和无来源检查继续拒绝。

客户提出简化器件后，玩具的独立存储改成条件候选。模块确认文案同步保留适用条件，明确功能电路路数不等于芯片数量；不能把“采用条件候选”变成强制增加独立芯片。尚未核实存播集成能力时，继续保留优先集成要求和有完成条件的资料核对任务，不冒称参考芯片一定支持或不支持。

实际内部整理超时时，下一步明确显示重试及已保存文档仍保留，不继续显示无人执行的“AI正在整理”。对于多个接口重复返回同一规范字段的模型输出，前置说明每字段只能返回一次，错误反馈指出重复的具体字段；原有冲突拒绝规则继续保留。
